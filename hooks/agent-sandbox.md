## Where you run

You run as a headless session inside an OS sandbox (`~/.claude/hooks/run-agent.sh`, settings in `~/.claude/hooks/agent-sandbox.json`), which shapes what works:
- Bash commands can reach only these hosts: {{HOSTS}}. If you have WebFetch, fetch any other page with it, not `curl`. If you don't, you can't read other hosts: say so in your reply's evidence where a source needs one.
- `gh` and the research scripts (`repo-health.sh`, `gcp-skus.sh`, `reddit-search.sh`) need the user's login, which the sandbox hides, so they run outside it. That works only if every command in the Bash call is `gh ...` or `~/.claude/skills/research/scripts/<script> ...`, joined at most by `;` or `&&`. Add a text filter, `cd`, `echo`, a loop, an assignment, `$(...)`, a redirect to a file, an absolute path or `bash`, and the whole call runs inside the sandbox: `gh` can't read its config, and `repo-health.sh` says `gh isn't logged in`. The guard refuses those calls. For several queries, write the `gh` commands one after another with `;` in one call, not in a `for` loop, and trim output with `--jq` instead of `head` or `grep` (`--jq '.content | @base64d | split("\n")[:40] | join("\n")'` reads the top of a file). Give `repo-health.sh` several repos at once.
- Bash runs reading and text tools, `curl`, `gh` and `git` (read-only) and the skill scripts, and nothing else. The guard refuses `awk`, `python3 -c`, shell functions, `>` into a file and `curl -o`, so use these instead: `sed -n '10,40p' <file>` or `grep -n` to read part of a file; `cut`, `sort`, `uniq -c` and `wc` to count; `jq` for JSON; `curl -s <url> | head` to read a page, and `curl -sI <url> | head -1` for its status. Keep output on screen: nothing needs a file.
- If you have WebSearch, a query may be at most 200 characters, in words: the guard refuses one holding a long run of letters and digits, which looks like a token or encoded data.
- Credentials (all of `~/.config` included), secret environment variables and session history (transcripts, prompt history, earlier agent runs) are unreadable to Bash, and a guard refuses the same reads to your other tools. Bash can't write under `~/code`, `~/notes` or `~/.claude`, your working directory included. A refusal that says `Operation not permitted` or `Blocked by agent-guard` is deliberate, not a bug. Don't try to get around it. Git's `warning: unable to access '~/.config/git/...'` is the same rule, and harmless.
